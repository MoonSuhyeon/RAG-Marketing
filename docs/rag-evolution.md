# RAG 파이프라인이 v1에서 v26까지 간 길

이 저장소의 검색 코어는 한 번에 설계되지 않았다. 26번 갈아엎으면서 남은 것이다.
**이 문서는 그 과정을 남기고, 코드는 최종본만 남긴다.**

버전별 구현 26벌(약 2.2MB)이 저장소의 97%를 차지하고 있었다. 배운 것은 코드가
아니라 **무엇이 효과가 있었고 무엇이 없었는지**라서, 그 판단만 여기 옮기고
구현은 지웠다. 각 버전의 원본은 git 이력에 남아 있다.

---

## 어디로 가고 있었나

처음 목표는 "PDF에 질문하면 답하는 것"이었다. 끝에서 남은 것은
**"모든 주장이 원본에서 왔음을 증명할 수 있는 검색·생성 파이프라인"** 이다.
목표가 바뀐 게 아니라, 무엇이 어려운 문제인지가 바뀌었다.

---

## 단계별 요약

### 1단계 (v1–v3) — 일단 돌아가게

| 버전 | 한 일 |
|---|---|
| v1 | Streamlit UI · HuggingFace 임베딩 · Ollama llama3.2 · PDF 파서를 PyPDF2 → pdfplumber |
| v2 | 로컬 모델 → OpenAI (`text-embedding-3-small` · `gpt-4o-mini`) |
| v3 | 청킹을 글자 수 → 문단·문장 단위, 거리 계산을 L2 → **코사인 유사도** |

L2에서 코사인으로 바꾼 게 첫 번째 진짜 교훈이었다. 임베딩은 방향이 의미를 담고
크기는 담지 않는다. 지표를 데이터의 성질에 맞추는 문제였고,
같은 종류의 판단이 나중에 [수요예측 프로젝트에서 제곱오차 대신 Poisson 우도를
고르는 결정](https://github.com/MoonSuhyeon/ML-Product)으로 다시 나온다.

### 2단계 (v4–v8) — 검색 품질

| 버전 | 한 일 |
|---|---|
| v4 | Multi-Query Retrieval(쿼리 리라이팅) + LLM 배치 리랭킹 |
| v5 | Overlap 청킹 · Semantic 청킹 |
| v6 | 컨텍스트에 `[출처 N]` 부여, 프롬프트로 3단계 구조 강제, 확신도 표기 |
| v7 | 멀티문서 3단계 추론 (청크 요약 → 공통점·차이점 → 종합) |
| v8 | 의도 분해형 쿼리 리라이팅 + 임베딩 pre-filter |

v6이 분기점이다. **출처 번호를 붙이자 "답이 그럴듯한가"가 아니라 "이 문장이
어느 청크에서 왔는가"를 물을 수 있게 됐다.** 지금 파이프라인의 사실 검증은
이 질문의 연장선이다.

### 3단계 (v9–v11) — 보이게 만들기

| 버전 | 한 일 |
|---|---|
| v9 | LLM 자동 평가 · 로그 저장/불러오기 |
| v10 | `Tracer` — Span 기반 단계별 추적, 모든 LLM 호출의 토큰 사용량 캡처 |
| v11 | 평가 점수 클램핑 버그, 출처 앵커 링크 버그 수정 |

v10에서 단계별 지연과 토큰이 보이기 시작하자 **어느 단계가 비싼지**가 드러났다.
리랭킹이 가장 비쌌고, 그래서 다음 단계의 방향이 "검색을 더 잘하기"가 아니라
"비싼 단계에 덜 보내기"가 됐다.

### 4단계 (v12–v16) — 숫자로 말하기

| 버전 | 한 일 |
|---|---|
| **v12** | **Dense(FAISS) + BM25 → RRF 융합** · md5 기반 디스크 임베딩 캐시 · NDCG@k |
| v13 | 쿼리 라우팅 — 질문 의도로 검색 전략 자동 선택 |
| v14 | Ablation Study — 구성 요소별 기여도 자동 실험 |
| v15 | 평가 고도화 + 오류 원인 분석 |
| v16 | 검색 품질 리포트 |

**v12가 지금 코드에 가장 많이 남아 있다.** Dense만으로는 고유명사·숫자에
약하고 BM25만으로는 의미가 다른 표현을 놓친다. 두 순위를 RRF로 합치는 방식이
그대로 `retrieval/core.py`의 `HybridIndex`가 됐다.

v14의 Ablation은 결론보다 습관이 남았다 — **구성 요소를 빼보고 성능이 안 떨어지면
그건 없어도 되는 것이다.** 이 습관으로 나중에 리랭킹과 Multi-Hop을 걷어냈다.

### 5단계 (v17–v21) — 스스로 고치기

| 버전 | 한 일 |
|---|---|
| v17 | Fallback 자동 재시도 — 평가가 나쁘면 스스로 다시 시도 |
| v18 | Dynamic Retrieval(의도별 프로필) + Answer Self-Refinement(초안 → 비평 → 개선) |
| v19 | 캐시 전략 분리 · Context Compression · Multi-Vector Retrieval |
| v20 | 실패 케이스 데이터셋화 + Auto Improvement |
| **v21** | 병렬 검색(4채널) · LongContextReorder · **Tool-Augmented RAG** |

**v21의 Tool-Augmented가 가장 중요한 교훈이다.** 수치 계산을 LLM에게 시키지 않고
Python에 위임하자 수치 환각이 0%가 됐다. 교훈은 "도구를 붙여라"가 아니라
**"틀리면 안 되는 것은 생성하지 말고 계산하라"** 였다.

이 문장이 지금 `FactValidator`의 존재 이유다. 편의시설·가격·인원은 생성 결과를
믿지 않고 원본 레코드와 대조한다.

### 6단계 (v22–v24) — 제품 모양으로

| 버전 | 한 일 |
|---|---|
| v22 | `MetricsCollector` 모니터링 · 인증/사용자 관리 · FastAPI 서버화 미리보기 |
| v23 | 모놀리식 단일 파일 → 3파일 분리 (engine / server / client) |
| v24 | `config.py` 분리 — 상수·경로·모델명 중앙화, 환경변수 오버라이드 |

v1~v22가 한 파일이었다. **한 파일이 420줄 요약을 필요로 하는 지경이 되어서야
쪼갰다.** 늦었지만, 쪼갤 때 경계가 이미 분명했던 건 그동안 어느 함수가 어느
단계에 속하는지 계속 추적해왔기 때문이다.

### 7단계 (v25–v26) — Agentic, 그리고 정량 검증

| 버전 | 한 일 |
|---|---|
| v25 | **Multi-Hop Reasoning** (질문 분해 → hop별 검색 → 종합) · **Self-RAG** (검색 결과가 충분한지 판단, 부족하면 쿼리 재작성 후 재검색) |
| v26 | **SSE 스트리밍** (`POST /chat/stream`) · **RAGAS 평가** 파이프라인 연결 |

v25의 Self-RAG가 남긴 것은 재검색 루프가 아니라 **"검색은 언제나 뭔가를
돌려준다"** 는 자각이다. 충분한지 판단하는 단계가 없으면 빈약한 근거 위에
그럴듯한 답이 만들어진다. 지금 `retrieval/core.py`의 `assess()` 가 그 자리다.

## 지금 코드에 남은 것

| 그때 | 지금 |
|---|---|
| v12 Dense + BM25 RRF | `retrieval/core.py` — `HybridIndex` |
| v12 md5 디스크 임베딩 캐시 | `retrieval/embedder.py` — `EmbeddingCache` |
| v25 Self-RAG 충분성 판단 | `retrieval/core.py` — `assess(hits, min_score, min_margin)` 기권 |
| v21 수치는 생성하지 말고 계산 | `app/engine/fact_validator.py` — 필드 단위 대조 |
| v17 Fallback 재시도 | 검증 실패 → 재생성 1회 → 그래도 실패하면 **거부** |
| v6 출처 번호 | 생성물의 모든 주장을 원본 필드로 되짚기 |
| v10 Span 추적 · 토큰 캡처 | 운영 지표(지연·토큰·캐시 적중) |
| v26 RAGAS | 평가 지표 3종 + 자체 지표(사실 정합성·환각 편의시설) |

## 버린 것과 이유

| 버린 것 | 왜 |
|---|---|
| **Multi-Hop Reasoning** (v25) | 원본이 정형 레코드다. 여러 홉으로 찾아 헤맬 필요 없이 **필드를 직접 읽으면 된다.** 문서 코퍼스였다면 남겼을 것 |
| **LLM 배치 리랭킹** (v4) | 메타데이터 필터가 후보를 96.9% 줄인 뒤라 비용 대비 이득이 작아졌다 |
| **LLM 자동 평가** (v9·v15) | **규칙 기반 검증으로 대체.** 결정적이라 테스트로 고정할 수 있고 생성당 추가 모델 호출이 없다 |
| **쿼리 라우팅** (v13) | 메타데이터 필터로 대체. 지역·인원·가격 같은 **업무 조건이 의도 추정보다 정확하다** |
| **Ablation Study** (v14) | 구성 요소가 줄어 실익이 작아졌다. 습관만 남겼다 |
| **문서 업로드 · 인증 · 채팅** (v22) | **제품이 달라졌다.** 문서 질의응답이 아니라 숙소 콘텐츠 생성이다 |

---

## 이 저장소가 배운 한 문장

**틀리면 값을 치르는 자리에서는 생성하지 말고 대조하라.**

v21에서 수치 계산으로 처음 배웠고, v25에서 "검색은 언제나 뭔가를 돌려준다"로
다시 배웠다. 지금 파이프라인이 없는 편의시설을 광고하지 않는 이유가 그것이다.
